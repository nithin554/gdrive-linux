gdrive-linux

Native Google Drive network drive for Linux — mount your cloud, zero disk used.

Features

Everything you need from a cloud drive, without the bloat.

📡

True Network Drive

FUSE virtual filesystem mounted at ~/Google Drive (email), accessible to every application on your system.

⚡

Pure Streaming

Reads stream from Drive API directly into memory. Writes buffer in RAM and upload on close. Nothing touches disk.

📁

Instant Listing

ls, file managers and stat use metadata only — zero network calls. Files appear instantly.

🌐

Infinite Storage

Your entire Google Drive is accessible with zero local footprint. No cache files, no placeholders, no downloads.

🕸️

System Tray

Right-click tray icon for account info, settings, manual sync, log out, and quit. Left-click opens your drive.

🔐

OAuth 2.0

Secure Google authentication via browser-based OAuth flow. Tokens stored in ~/.config/gdrive-linux/.

🔄

Account Switching

Log out and log in with a different Google account without restarting the application.

🚫

Delete Protection

Accidental deletions are blocked with a warning notification to prevent permanent data loss.

📦

Cross-Distro Packages

Available as .deb, .rpm, .pkg.tar.zst and universal AppImage.

How It Works

A FUSE virtual filesystem that streams everything on demand.

   User / app reads file content
            │
            ▼
     FUSE intercepts read()   ← open()/stat() are free (zero network)
            │
            ▼
     FUSE streams from Drive API   ← content goes into memory (never disk)
            │
            ▼
   User edits file
            │
            ▼
     FUSE uploads to Drive on close  ← dirty buffer sent to Drive API

OAuth Verification & Privacy

What data gdrive-linux accesses, why, and how it's handled.

🔍 Scopes Requested

gdrive-linux requests the following OAuth scopes from your Google account:

  1. https://www.googleapis.com/auth/drive.readonly — Read access to file metadata (names, sizes, types, modification times) and content. Used to list and open your files.
  2. https://www.googleapis.com/auth/drive.file — Per-file read/write access to files created or opened by the app. Used to save changes you make.
  3. https://www.googleapis.com/auth/userinfo.email — Read-only access to your email address. Used to label the mount point (e.g., ~/Google Drive (user@gmail.com)) and display your account in the tray menu.

🛡️ Privacy & Data Handling

  1. No data stored on disk. File content is streamed directly from Google Drive into memory and never written to your local storage.
  2. Nothing leaves your machine except what you explicitly write back to Google Drive. No telemetry, no analytics, no external servers.
  3. Token security. Your OAuth token is stored in ~/.config/gdrive-linux/token.json (permissions 600). It is never shared or transmitted anywhere except to Google's token endpoint.
  4. No third-party services. gdrive-linux communicates exclusively with googleapis.com. No other servers are contacted.
  5. Open source. The entire codebase is MIT-licensed and fully auditable on GitHub.

💳 Verification Details for Google OAuth

This section documents how gdrive-linux uses OAuth, which is required for Google's OAuth verification process (sensitive / restricted scopes review).

  1. Application Type: Desktop application (Python + PyQt6). OAuth flow uses the loopback redirect URI (http://localhost).
  2. Authentication Flow: PKCE (Proof Key for Code Exchange) OAuth 2.0 flow. No client secret is sent over the wire. The user authorizes via their browser.
  3. Token Storage: Credentials are saved to ~/.config/gdrive-linux/token.json after first authentication. They are refreshed automatically using the refresh token when expired.
  4. Data Access Justification:
    • drive.readonly + drive.file — Required to present your Google Drive as a mounted filesystem and allow read/write operations.
    • userinfo.email — Required to identify the account being used (displayed in the mount point path and tray menu).
  5. No data shared with third parties. All API calls are made directly from the user's machine to www.googleapis.com.
  6. Data deletion: Users can revoke access at any time from their Google Account Permissions page. The "Reset All Data" option in the app tray menu also deletes the local token.

Usage

From launch to your files — it just works.

1

Launch the application

Run gdrive-linux from your terminal or application menu. It authenticates with Google Drive and mounts the network drive automatically.

2

Files appear instantly

Your entire Google Drive is mounted at ~/Google Drive (<email>). Files show up with real sizes — zero bytes stored locally.

3

Open, edit, save

Open a file — content streams from Drive into memory on demand. Edit and save — changes upload to Drive when you close the file.

4

Use the tray icon

Left-click opens the drive in your file manager. Right-click shows account info, settings, manual sync, log out, and quit.

5

Switch accounts or reset

Go to Settings → Log out to switch Google accounts. Use "Reset All Data" to clear token, cache, and mapping — all at once.

Configuration

Environment variables and auto-generated config files.

⚙️ Environment Variables

Variable Purpose
GDRIVE_CLIENT_ID Google OAuth client ID
GDRIVE_CLIENT_SECRET Google OAuth client secret

📄 Config Files (in ~/.config/gdrive-linux/)

File Purpose
token.json Google OAuth token (auto-generated)
sync_mapping.json Local path ↔ Drive file ID mapping
settings.json Application preferences (autostart, etc.)
